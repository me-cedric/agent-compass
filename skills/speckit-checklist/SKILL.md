# Spec Kit Checklist

Read `AGENTS.md`, `spec.md`, and any domain docs that define acceptance rules.

## Do

1. Build checklists that prove readiness, not generic ceremony.
2. Include content quality, requirement completeness, security/privacy, UX, docs,
   contracts, env, and validation items only when relevant.
3. Keep each item objectively checkable.
4. Mark unchecked items honestly; do not auto-pass incomplete work.

## Done

- Checklist lives with the feature artifacts.
- Failing items explain the required follow-up.
